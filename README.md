

Цель этого ДЗ

Спроектировать и реализовать HTTP API для простого web-сервиса модерации объявлений. Реализовать тест-кейсы для написанных эндпоинтов.


Сетап



Сервис разрабатываем на Python с использованием фреймворка FastAPI.

Сервис должен иметь один обработчик `predict`, который принимает на вход:

seller_id: int

is_verified_seller: bool

item_id: int

name: str

description: str

category: int

images_qty: int



На выход данный обработчик должен вернуть лишь одно булево значение.



На данном этапе реализуем наивную проверку, будем считать что подтвержденные пользователи всегда публикуют объявления без нарушений, а не подтвержденные только при наличии изображений (в следующих занятиях будем добавлять функционал и добавлять модель для предсказания).



Что вам нужно сделать

1. Создайте базовый репозиторий 

1.1. Создайте репозиторий в своей GitHub и клонируйте на локальную машину

1.2 Установите локально fastapi

Для этого используем команды

pip install fastapi

pip install fastapi[standard]



1.3 Создайте главный файл решения main.py с содержимым







from fastapi import FastAPI

from routers.users import router as user_router



app = FastAPI()



@app.get("/")

async def root():

   return {'message': 'Hello World'}





2. Опишите обработчик /predict

Опишите принимаемые аргументы и провалидируйте их

Опишите формат возвращаемого значения

Опишите базовую логику предсказания


3. Напишите unit-тесты

Проверьте положительный результат предсказания

Проверьте отрицательный результат предсказания

Проверьте валидацию значений (на соответствие типам и наличие обязательных аргументов)

Проверьте обработку ошибки, если вдруг она возникнет на уровне бизнес-логики

К концу задания ваш сервис:

умеет предсказывать есть ли в объявлении нарушения

имеет тесты, которые позволят найти ошибки при дальнейшей разработке



Что и как вы отправляете на проверку

На проверку нужно отправить ссылку на коммит с изменениями по текущему домашнему заданию.









Критерии оценивания

Максимальный балл – 10. 



1. Корректный обработчик — 0–2 балла

0 баллов — обработчик не соответствует заданному API.


1 балл — обработчик соответствует заданному API.


2 балла — обработчик имеет валидацию входящих аргументов и возвращает значение заданного значения.

2. Правильная логика валидации объявления — 0–1 балла

0 баллов — логика не соответствует заданной.


1 балл — логика соответствует описанной в задании.


3. Соответствие принципам чистой архитектуры (структура проекта, разделение логики) — 0–1 балла

0 баллов — код монолитный, бизнес-логика смешана с роутами.


1 балл — выделены уровни routes и services.


4. Локальный запуск без ошибок — 0–1 балл

0 баллов — проект не запускается или требует ручных доработок.


1 балл — проект разворачивается и запускается локально без ошибок через fastapi dev


5. Тесты — 0–3 балла

0 баллов — тесты отсутствуют.


1 балл — есть тесты на позитивные и негативные сценарии, но нет обработки corner-cases.


2 балла — тесты покрывают все возможные corner-cases.


3 балла — в тестах используется параметризация для проверки corner-cases чтобы уменьшить дублирование кода.


6. Прохождение тестов — 0–1 балл

0 баллов — часть тестов падает или не запускаются.


0.5 балла — тесты запускаются, но не все проходят.


1 балл — все тесты проходят успешно.


7. Предсказуемые статусы (200, 400, 500) — 0–1 балла

0 баллов — при ошибках возвращается 500 или пустой ответ.


1 балл — сервис корректно возвращает HTTP-ошибки с понятными сообщениями и статусами, неизвестная ошибка в бизнес-логике 500, ошибка валидации 400.
